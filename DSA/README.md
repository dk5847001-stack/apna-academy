----------------------------------------------------- DSA REACT APP STRUCTURE ------------------------------------------------
# ApnaAcademy DSA — React App

A production-ready, scalable and premium **DSA Learning + Coding Practice Platform** built as a separate React + Vite application inside the ApnaAcademy ecosystem.

The DSA application is intentionally separated from the main ApnaAcademy Frontend, Dashboard, Course and Admin applications, while remaining connected to the central ApnaAcademy authentication, student identity, subscription, payment and entitlement systems.

---

# 1. Product Vision

ApnaAcademy DSA is not only a question-list application.

It is designed as a complete:

* DSA Learning Platform
* Topic-wise Coding Practice Platform
* Company-wise Interview Preparation Platform
* Online Coding Workspace
* Student Progress Tracker
* DSA Study Plan Platform
* Competitive Practice Platform
* Performance Analytics Platform
* Premium DSA Subscription Product

The platform should provide a clean experience similar to modern coding-practice platforms while maintaining ApnaAcademy's own premium UI, branding and ecosystem.

---

# 2. DSA Application Position in ApnaAcademy

The complete ApnaAcademy ecosystem is structured as:

```text
ApnaAcademy/
│
├── Frontend/          # Public Website + Authentication
├── Dashboard/         # Student Dashboard
├── Course/            # Course Learning Platform
├── Admin/             # Main Admin Panel
├── DSA/               # Separate DSA Platform
└── Backend/           # Central ApnaAcademy API
```

The DSA application must remain a separate React + Vite application.

```text
                         ApnaAcademy
                              │
             ┌────────────────┼────────────────┐
             │                │                │
          Frontend         Dashboard         Course
             │                │                │
             └────────────────┼────────────────┘
                              │
                       Central Backend
                              │
             ┌────────────────┼────────────────┐
             │                │                │
          Auth             Student        Subscription
                              │                │
                              └───────┬────────┘
                                      │
                                      ▼
                                DSA Application
                                      │
                     ┌────────────────┼────────────────┐
                     │                │                │
                  Topics          Companies        Practice
                     │                │                │
                     └────────────────┼────────────────┘
                                      │
                              Progress / Submit
```

---

# 3. Core Architecture Principle

The DSA frontend is independent, but the user identity and premium entitlement must remain connected to ApnaAcademy.

The user should NOT need a separate DSA account.

```text
ApnaAcademy Login
        │
        ▼
Authenticated User
        │
        ▼
DSA Application
        │
        ├── Profile
        ├── Progress
        ├── Solved Problems
        ├── Submissions
        ├── Bookmarks
        └── Premium Access
```

The same student identity should work across:

```text
ApnaAcademy
Dashboard
Course
DSA
```

---

# 4. Technology Stack

## Frontend

* React
* Vite
* React Router
* Tailwind CSS
* Axios
* Lucide React / approved icon library
* Modern React Hooks
* Context API where appropriate
* Lazy loading
* Code splitting

## Backend Integration

* REST API
* Axios service layer
* HttpOnly authentication cookies
* Central ApnaAcademy Backend
* Subscription/entitlement API

## Database

The DSA domain data should be stored server-side.

The frontend must NOT contain the complete question database in static JSON.

# 13. Premium Lock Architecture

Premium access must be enforced by the backend.

Frontend-only locking is NOT sufficient.

```text
Frontend
   │
   ▼
GET problem
   │
   ▼
Backend
   │
   ├── User authenticated?
   │
   ├── Problem free?
   │
   └── Premium entitlement active?
          │
          ├── YES → Return accessible content
          │
          └── NO → Return locked state
```

The solution/editorial/test cases for locked content should not be unnecessarily exposed to an unauthorized client.

      ▼

      │
      ▼

# 63. Important Architecture Rules

These rules must remain valid throughout development.

### Rule 1

DSA must remain a separate React + Vite application.

### Rule 2

DSA must use the ApnaAcademy identity ecosystem.

### Rule 3

Do not create a second independent student account system unnecessarily.

### Rule 4

Premium access must be verified by the backend.

### Rule 5

Never expose hidden test cases.

### Rule 6

Never execute user code directly inside the primary API process.

### Rule 7

Do not store the entire problem database in frontend JSON.

### Rule 8

Use pagination for large datasets.

### Rule 9

Company and topic relationships must be many-to-many.

### Rule 10

All API communication must use service modules.

### Rule 11

All premium/payment state must have server-side authority.

### Rule 12

The DSA frontend should remain independently deployable.

### Rule 13

Existing ApnaAcademy applications must continue working independently.

### Rule 14

New DSA functionality must not break existing authentication, courses, purchases or dashboard functionality.

### Rule 15

Every future feature should be added without unnecessarily rewriting the existing architecture.
